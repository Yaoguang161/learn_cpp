# 1. C++基础

## 1.1 内存分配与智能指针

### 1.1.1 介绍一下`new`和`malloc`

1. `new`操作符  

   `new T`或者`new T[N]`时，先调用底层的`operator new`或者`operator new[]`, 作为一个可重载的函数，由C++运行库提供默认实现， 分配足够大小的原始内存。会间接调用`malloc`来向操作系统请求内存。    

   `new`操作符会自动调用对象的构造函数来初始化这块内存， 例如`int, double`, `new`也会进行零初始化和默认初始化。  

   `new`返回的是指定类型的指针， 无需进行强制类型转换，有更好的类型安全性。  

   在操作系统方面`operator new`会通过系统调用（例如`sbrk` 扩展数据段或`mmap`映射匿名文件在`linux`上,`VirtualAlloc`在win上），向操作系统向操作系统请求一块虚拟内存。而实际的物理内存只有在第一次访问时才会被分配和映射，这称为缺页中断。  

2. `malloc`函数

   纯粹的内存分配，以字节为单位，返回一个`void *`类型的指针，指向内存的起初地址，然后需要进行显式类型转换，降低了类型安全性，而且分配内存失败会返回`NULL`，需要显式检查返回值。

### 1.1.2 当`new `一个对象数组时例如`new Myclass[10]`发生了什么？为什么需要匹配`delete[]`

1. 使用`operator new[](size_t)`时，编译器计算整个数组的总内存大小，不仅是`10 * sizeof(Myclass)`,还会额外分配一些内存，例如`sizeof(MyClass)`是X，那么分配的总大小是`X*10 + Y`,其中Y是存储数组大小的额外空间，这也是`delete[]`依赖这部分数据来知道要销毁多少个对象（调用多少次析构函数）。
2. 内存分配成功后，会进入循环，为每一个对象以此调用默认构造函数。
3. 提供匹配的`delete[]`会查找内存头数存储的元数据，例如10，然后逆序调用析构函数，防止对象之间可能存在的依赖关系。



### 1.1.3 介绍一下智能指针`std::shared_ptr`的引用计数， 包含了哪些数据？原子性如何保证？为什么不能简单使用`int`变量？

1. 核心思想：多个`shared_ptr`对象可以共通拥有一个资源，当最后一个对象不再拥有该资源时(被销毁被重新赋值或者离开作用域时)，资源才会被自动释放。当一个`shared_ptr`被创建或被拷贝时，会指向一个控制块，控制着被管理对象的信息，其中包括强引用计数和弱引用计数。`std::atomic`原子操作来保证线程安全(互斥性和内存同步)，如果简单地使用一个普通的 `int` 变量来作为引用计数，而在多线程环境下对其进行增减操作，就会导致严重的**竞态条件（Race Condition）**。
2. `shared_ptr`包含了裸指针和控制块指针, 控制块在堆上分配，包括了强引用计数，弱引用计数，被管理对象的裸指针，删除器，分配器。`



### 1.1.4 `std::unique_ptr`、`std::shared_ptr` 和原始指针，并给出各自的适用场景。
原始指针
1. 没有所有权语义，能指向堆上对象，栈上对象，甚至非法内存地址
2. 容易出现悬空指针，重复释放和内存泄露。

`unique_ptr`

	1. 只有一个实例独占它管理的对象，被销毁时自动删除所指向的对象。
	1. 可以通过移动语义(std::move)将所有权从一个`unique_ptr`移动到另一场`unique_ptr`, 不能拷贝
	1. 使用场景： 作为函数的返回值，用于安全地转移动态分配对象的所有权；将所有权从一个容器移动到另一个容器时；作为类对象，独占某个资源的时候。

`shared_ptr`

1. 共享所有权
2. 每次拷贝构造和赋值操作符进行拷贝时，都会增加引用计数
3. 使用场景： 当需要将一个对象传递给回调函数或异步操作，并且不确定何时这些操作会完成时。在工厂模式中，返回一个共享所有权的对象。  



在性能上`unique_ptr`和原始指针几乎差不多, `shared_ptr`几乎是原始指针的两倍，包括了指向对象的和指向控制块的。

## 1.3 虚函数详解

1. 虚函数表，是编译器在编译时为每个虚函数或继承了虚函数的类生成的静态数组。
2. 虚函数表中存储的是该类中**所有虚函数的函数指针**
3. 一个类只有一个虚函数表
4.  如果派生类没有重写（override）基类的虚函数，那么派生类的虚函数表中对应位置仍然会指向基类的虚函数实现。



## 1.4 左值与右值

### 1.4.1 左值

可以出现在赋值运算符左边的表达式，即可以被赋值，你可以通过取地址运算符 `&` 来获取它的地址，并且有名称。大多数左值是可以被修改的，除非const

举例： 

	* 变量名：`int x;` 中的 `x`。
	* 解引用指针：`*ptr`。

###  1.4.2 右值

右值是临时的，没有持久的内存地址，不能取地址，右值通常是不可修改的

举例：

	* 字面量：`10` (整型字面量), `3.14` (浮点型字面量), `true` (布尔字面量)。
	* 算术表达式的结果：`a + b`。
	* Lambda 表达式的结果：`[](){ return 42; }()`。这里赋值给左值后就消失。
	* 类型转换的结果：`static_cast<double>(some_int)`。

### 1.4.3 左值引用

为已经存在的对象创建一个别名， 同时延长声明周期，const 左值引用可以绑定到右值，并且延长右值声明周期到引用的声明周期结束。

### 1.4.4 右值引用

只能绑定到右值，引入的目的是为了实现移动语义。

例如`vector`的移动构造函数可以直接交换两个vector的内部缓冲区指针，而不需要复制所有的元素。

## 2.1 链表

链表： 插入和删除高效（O(1)), 随机访问效率(O(N))

判断是否有环？  

使用快慢指针，如果最终相遇，则有环。

删除倒数第N个节点： 双指针法， 让一个快指针先走N不， 然后两个指针再同时走，先走的指针到达末尾时，第二个慢指针就是要删除的节点。

相邻的两个节点 `n0` 和 `n1` 之间插入一个新节点 `P` ，**则只需改变两个节点引用（指针）即可**，时间复杂度为 O(1) 。

即： 

```
P.next = n1;  //令P指向n1
n0.next = P;  //令n0指向P
```



双向链表的特点： 

	* 包含两个指针，操作高效，任意位置删除插入都是O(1)， 不会使其他迭代器失效
 * 随机读取效率低O(N);
 * 支持双向遍历

## 2.6 list（双向链表）

优点：

* 任意位置删除插入都是O(1)， 不会使其他迭代器失效

缺点： 

	* 随机访问是O(N)



使用场景： 在高频插入删除，但不随机读取的场景下使用。

## 2.7 vector (动态数组)

优点： 

* 随机快速访问： O(1)
* 连续内存，尾插和尾删高效
* 适用需要频繁随机访问元素。
* 元素在内存中连续存储，有利于 CPU 缓存的利用，提高访问速度。

缺点： 

	* 中间插入效率低



使用场景：尾部增删，同时需要随机访问的场景。



## 2.8 deque（双端队列）

优点： 

* 随机快速访问： O(1)， 但由于内存不完全连续，差于vector
* 尾插和尾删高效，头插和头删效率高
* 适用需要频繁随机访问元素。

缺点： 

 * 中间插入效率低
 * 由于不保证内存连续，可能不如 `std::vector` 那么缓存友好



使用场景：需要随机访问能力，同时需要两端插入和删除的场景。



## 2.9 queue（队列)

优点： 先进先出 (FIFO)

缺点： 只能访问队头和队尾元素。
